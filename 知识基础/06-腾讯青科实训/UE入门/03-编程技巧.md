## 编程技巧
### 游戏框架
1. GameMode(游戏模式)
    - 游戏模式类负责设置正在执行的游戏的规则
    - 规则可以包括玩家如何加入游戏，是否可以暂停游戏，关卡过渡，以及任何特定的游戏行为(例如获胜条件)

2. GameState(游戏状态)
    - 游戏状态包含要复制到游戏中的每个客户端的信息，它表示整个游戏的"游戏状态"
    - 它通常包含有关游戏分数，比赛是否已经开始和基于世界场景玩家人数要生成的AI数量的信息等等

3. PlayerState(玩家状态)
    - 玩家状态是游戏玩家的状态，非玩家AI将不会拥有玩家状态
    - 玩家状态中的数据包括玩家姓名或得分、当前等级或生命值等

4. Pawn(兵卒)
    - Pawn是Actor的一个子类，充当游戏中的生命体

5. Character(角色)
    - Character是Pawn Actor的子类，用作玩家角色
    - 角色子类包括碰撞设置、双足运动的输入绑定，以及由玩家控制的运动附加代码

### Blueprint（蓝图）
蓝图是什么？蓝图是可视化表示游戏世界的一种方式
分类:
- Level Blueprint
    - 自动创建，每个Level一个
    - 生命周期是整个关卡存在的时间
    - 监听Level级别的事件
- Blueprint Class
    - 自己可以随意添加，需要继承已有的类
    - 可以添加不同的组件来丰富功能
    - 通常被放置在关卡中，执行自身的逻辑功能
- Data-Only Blueprint
- Blueprint Interface
- Blueprint Macros

使用：
- 从监听的事件开始
- 其他Actor接口调用
    - 从关卡中拖进来Actor，调用其接口
    - 右键选择系统提供的默认Actor
- 调用蓝图库中的函数

**Blueprint与C++之间的成员变量**
```C++
UPROPERTY(Category = "My Category", EditAnywhere)
  uint32 bUseOffset : 1;
UPROPERTY(Category = "My Category", EditAnywhere, meta = (EditCondition = "bUseOffset"))
  FVector Offset;
```

**Blueprint与C++之间的相互函数调用**
- UFUNCTION(BlueprintCallable) : C++中实现函数体，蓝图中调用
- UFUNCTION(BlueprintNativeEvent) : C++中实现默认函数体，蓝图中可以选择重载
- UFUNCTION(BlueprintImplementableEvent) : 蓝图中实现函数体，C++中声明和调用

缺点:
- 容易形成蜘蛛网
- 二进制格式，Diff和Merge不方便

使用原则：
- 用于数值配置
- 用于简单的效果展示
- 用于特别简单的逻辑功能

### C++ in UE
编码规范:
- T-模板类的前缀: i.e. TArray, TMap, TQueue
- U-继承自UObject的类的前缀: i.e. UTexture
- A-继承自AActor的类的前缀: i.e. AGameMode
- F-structs及其他多数类均以F为前缀: i.e. FName, FVector
- I-抽象接口类前缀: i.e. ITransaction
- E-枚举类型的前瞻: i.e. ESelectionMode
- b-布尔类型必须以b开头: i.e. bIsEnabled

基本类型:
- **不使用C++原生的整形(char, short, int, long, etc.)**
- **自定义ints & strings in GenericPlatform.h(int32, uint32, uint64, TCHAR, ANSICHAR, etc.)**

#### UObject

- Serialization from/to disk and over the network
- Garbage collection
- Meta data
- Also: Blueprint Integration

Magic Macros

- USTRUCT - 结构体
- UFUNCTION - 成员函数
- UPROPERTY - 成员变量
